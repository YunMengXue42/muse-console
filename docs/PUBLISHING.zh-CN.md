# 公开发布检查清单

[English](PUBLISHING.md) · [中文 README](../README.zh-CN.md)

本文用于准备公开源码，不会自动改变仓库可见性、发布软件包、轮换凭据或修改运行中的服务。

## 1. 当前文件与历史

在仓库根目录执行：

```bash
python tools/check_publication.py
python tools/check_publication.py --history
```

默认检查已跟踪的工作区文件；`--history` 检查所有**本地引用**可达的历史文件对象与提交/标签元数据。结果只包含路径、对象 ID 和行号，不回显匹配值。规则覆盖部分令牌/私钥格式、长会话 Cookie、私密 AI 会话引用及私密运行数据路径，不是完整秘密扫描器、安全审计或凭据失效证明。

- 人工复核误报；测试使用简短且明确虚构的凭据。
- 检查所有分支、标签和历史删除文件，而不只看最新目录。需审计远程历史时，在获得授权后获取相关引用；不完整的本地克隆不能证明远端历史已清理。
- 人工检查提交/标签说明、作者/提交者身份、标签签署者邮箱和 Git notes。工具只输出非 noreply 提交/标签邮箱的摘要供复核，不自动改写或判断哪些身份可公开。
- 人工检查图片、字体、压缩包、构建后的 JavaScript、source map 和第三方许可证；工具不全面解码二进制内容。
- 保留上游归属，不为“重新开始”而抹去第三方作者信息。

## 2. 私密数据边界

不要提交或作为附件上传 `.env`、`data/`、`data-preview/`、SQLite 数据库及边车文件、Cookie、HAR、浏览器配置目录、生成媒体、部署密钥、备份或真实验收日志。`.gitignore` 只防止意外新增跟踪，不能擦除历史，也不能让泄露过的凭据重新安全。

导出源码用 `git archive`，不要直接压缩整个工作目录；上传前检查实际压缩包。完整停写备份包含秘密，即使数据库载荷已加密，也必须与公开交付物分开保存。

发现历史真实凭据时：

1. 在所有者批准后撤销/轮换凭据；改写历史不等于撤销凭据。
2. 保留私密备份，在独立副本中准备干净历史。
3. 改写共享分支/标签、强推前取得批准；通知协作者新的提交 ID，并同步部署与回滚引用。
4. 再次扫描清理后的历史；复核远程引用、Release/附件、CI 日志/产物及缓存。旧克隆和 fork 仍可能保留内容。

不要把删除本机已忽略的运行数据当作公开内容清理。

## 3. 验证与文档

- 按 [贡献指南](../CONTRIBUTING.zh-CN.md) 完成锁定安装、格式、静态检查、后端/前端/扩展测试和打包检查。
- 中英文 README、部署、贡献和安全指南保持一致，核对相对链接与版本号。
- 示例不得出现个人生产域名/IP、账号邮箱或本机绝对路径；使用 `example.com`、回环地址和明确占位符。
- 保留 [LICENSE](../LICENSE)、上游归属、字体许可证和依赖声明。
- 检查 wheel 和源码包实际内容，不包含数据、浏览器配置、秘密、虚拟环境或 `node_modules`。
- 区分离线/mock 测试与真实认证、生成、续期验收，不宣传未经验证的能力。

## 4. 托管设置与最终确认

保持仓库私有时，另外复核 GitHub Release（包括草稿/附件）、Actions 日志/产物、Issue/PR 附件、Wiki、Pages、仓库简介/主页和集成。上述表面不在本地检查器的覆盖范围内。

复核 Actions 默认只读权限、外部 PR 执行方式、可用的秘密扫描/推送保护、分支保护及私密漏洞报告入口。确认 [安全策略](../SECURITY.zh-CN.md) 与实际已启用功能一致；新增集成和权限必须取得批准。

改变仓库可见性前取得所有者明确的最终批准。GitHub 可见性变化会影响 fork、Actions 历史及其他功能，提交操作前阅读当时的确认页面与官方说明。公开源码不等于发布生产部署、PyPI 包、容器镜像或浏览器扩展。
